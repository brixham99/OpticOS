# OpticOS 128: SCREEN 1 (32-column) plan

Plan only — no ROM code, no commit, no push. Branch `opticos128-ext`.

Numbering: **0** = 64-column hi-res; **1** = 32-column hi-res with the new 8×8 font, same 256×192 bitmap (PLOT/DRAW are the main-ROM path); **2** = chunky 64×48 (old 1); **3** = attribute 32×24 (old 2). Text in 2 or 3 returns to the **last text mode** (0 or 1). `OMODE` ($5C92, already 64 at boot) holds 64 or 32. `SMODE` bits 0–1 are 0–3; bits 3 and 7 stay FLIP.

**(a) 32-column printing.** Font and renderer live in the extension ROM (glyph, wrap, AT 0–31, TAB, backspace, comma at 16-column stops, CR, scroll, attributes, INVERSE/OVER). RST 16 already goes to `x_txt` (21 bytes, gap up to NMI). Rewrite: mode 0 falls into `print_a`; modes 1–3 do `ld e,4 / call xgo` with the character in D. The extension restores 2/3 from `OMODE` (32 → `SMODE` 1, else 0), shows screen 5, then prints 8×8 or far-calls `print_a`, and returns via `x_back`. Change `pr_msg` / `err_show` from `call pr_out` to `rst 16` so errors follow the hook (saves two bytes). Leave `PR_OUT` in page $09 for `POKE 23739,111`. `xchk` (PLOT/DRAW/CLS): `or a` → `and 2` (same size) so mode 1 stays on the hi-res path; CLS in mode 1 is the existing bitmap clear and a homed cursor. Console must stop forcing `SMODE=0`; pad to keep `x_rst` at $05D7 (published far-return). If BREAK can skip RST 16, still restore last text mode before paging screen 5. Parameterise `lin_pos` / `pos_lin` / `cur_set` from `OMODE` (×32, 8-pixel cursor, columns 0–31). A 126-character INPUT line then spans four rows.

**(b) Main-ROM bytes.** v1.0.4 has 116 free; this branch already spent 32 of those on SCREEN/SAY hooks (plus the 14-byte statement hook), leaving 81 slack. Remaining clean gaps of 4+: **14 bytes** at $000B (5), $002B (5), $2038 (4). `x_txt` should fit its 21-byte slot; `xchk` is the same size; CIRCLE needs no new hook (`ext_hook` already offers unknown names). New cost: editor width ~20–25; G-mode and allowing 144–164 in the editor ~15–25; optional `USR "a"` ~20–25; a tokeniser guard (144–164 legal only inside strings) ~8–12. Spend the 14 gaps and the `pr_msg` saving first; if still short, tighten `console.asm` / `print.asm` / `keyboard.asm` (shared `OMODE` helper; Caps+9 already emits 15, which the editor ignores). Don’t casually eat more of the 81 beyond the 32-hook share.

**(c) Extension-ROM space.** Before: **2,610 free** ($31BE–$3AFF and $3B10–$3BFF). SAY ends $28AD; screen $28AD–$31BE; TA2 $3B00; TA $3C00; AY volume $3D00–$3FFF. After, packed below $3B00: font 768; 32-column printer ~300–400; hi-res CIRCLE backend ~80–120 (reuse the ~240-byte midpoint `circ` / `ci_oct` / `cpt`); mode-1 UDG draw ~30–50. About **1.2–1.4K**, leaving about **1.2–1.4K**. Don’t move the TA/AY tables.

**(d) Renumbering.** `SCREEN n` allows 0–3. `SCREEN 1` sets `OMODE=32`, `SMODE=1`, and uses OpticOS CLS (no chunky fill). `SCREEN 2`/`3` are today’s 1/2 and leave `OMODE` alone. `SCREEN 0` sets `OMODE=64` and CLS as now. POINT, BOX, FLIP, `plot_cl`, `ytotop`: mode 1 is hi-res; 2 and 3 are chunky/attr. Update `tools/rig/test_screen_gfx.py`, `tools/fuse_screen128.py`, `docs/opticbasic128-screen.md`, `tools/rom_map.py`, and `docs/screenmodes/` captions/filenames. `flags128.bas` and `circles128.bas`: old 1→2, old 2→3; add a short SCREEN 0/1 CIRCLE (and a mode-1 UDG line) when the demos are revised. README’s “32-column mode under consideration” becomes this SCREEN 1 — not a revival of the dropped `MODE 32` keyword.

**(e) INPUT, editor, LIST, CLS in mode 1.** CLS is the main-ROM hi-res clear. INPUT shares the console editor, so it needs the `OMODE` cursor/index fix. LIST already uses RST 16, so it wraps at 32 and still pauses every 23 rows. `AT y,32` is a screen error. After a program in 2/3, PRINT, LIST, errors, INPUT and the editor resume in the last text mode; the picture stays until CLS.

**CIRCLE in 0 and 1.** Claim the name in every mode (drop the dispatcher’s mode-0 skip). Reuse the midpoint routine; `plot_cl` gains a 256×192 backend onto screen 5, origin bottom-left, clipped, `r=0` the centre. Colour with no `c`: like PLOT — OVER/INVERSE on the pixel, `ATTR_T` into the cell with `MASK_T`. With `c` (0–15): set the ink pixel (unless INVERSE) and write INK+BRIGHT from `c`, leaving PAPER. Out of range is “Value outside range”. Main ROM: 0 extra bytes. 48K: still “No such PROC or FN”.

**UDGs (mode 1 only).** ZX BASIC-style, from general practice, not the Sinclair ROM: 21 bitmaps, codes 144–164, eight bytes each, POKEd from BASIC. The 168 bytes are **already reserved**: boot sets `RAMTOP = P_RAMT−168`, `UDG = RAMTOP+1` ($5C7B). Keep that slot above RAMTOP. `CLEAR n` must not let RAMTOP run into it, and must leave `UDG` pointing at it (or relocate both). The area is already zeroed, so un-POKEd UDGs are blank. Mode 1: the extension printer draws 8×8 from `(UDG)+8×(code−144)`. Mode 0: ignore 4×8 layout; 144–164 print as **`?`** (the existing ≥128 path). Display only — do not rewrite the byte, so EDIT’s capture channel still stores 144–164. Codes 128–143 stay `?`.

Entering: a **G-mode** bit in `KS_MODE`, toggled by Caps+9 (reuse the unused 15). While on, a–u / A–U insert 144–164; toggle again or ENTER to leave. Offer G-mode in mode 1 only. An escape prefix would work but is worse to type. Keywords are $80–$CB, so 144–164 collide as statement bytes: accept them only inside strings (`$06` + length + raw bytes); outside, a syntax error. LIST’s string path already does `rst 16`; EDIT copies through `cap_ch`, so raw codes survive. The console must allow 144–164 in `EBUF` (it rejects ≥128 today). `USR "a"` is feasible in every mode (it only returns an address). Today `USR` is integer-only; extend `f_usr` so a one-character string a–u / A–U returns `UDG+8×(ch−'a')`, any other string a type error (~20–25 bytes). Defer if the editor/G-mode squeeze comes first (`PEEK UDG` still works).

**(f) Risks.** Editor width, G-mode and `USR "a"` are the main-ROM budget risk; printing fits in existing hooks plus the 14-byte gaps. Leaving `pr_out` on the error/`cont?` path would make mode 1 (and UDGs) look 64-column. `x_rst` / `ext_back` must not move. `SCREEN 0`/`1` already CLS, so a stale column ≥32 is cleared. LIST in mode 0 must show `?` without turning stored 144–164 into `?`; leakage outside strings would detokenise as keywords. `CLEAR n` vs the 168 bytes above RAMTOP. 48K: no extension, so no SCREEN/CIRCLE/32-column/UDG glyphs; existing rigs must still pass. Check mode-1 PLOT over 8×8 text, and CIRCLE colour clash, by eye.

The font stays untracked under `fonts/` until this is implemented.
